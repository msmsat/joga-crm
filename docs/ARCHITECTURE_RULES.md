# Архитектурные правила

Рабочий свод правил для любых изменений в коде. Технический стек, структура папок и дизайн-система
описаны в [`CLAUDE.md`](../CLAUDE.md) — здесь **не дублируем**, только процессные правила.

---

## 1. Reuse before Create

Перед созданием компонента, хука, хелпера, утилиты, сервиса, стора, API-клиента, валидации,
типа, интерфейса или константы — **сначала ищем по всему проекту**.

Есть эквивалент → переиспользуем или расширяем. Копию не создаём.

Типовые места, куда смотреть в первую очередь:

| Что ищем | Где лежит |
|---|---|
| UI-компоненты | `front/src/components/ui/` (кит) — таблица в CLAUDE.md §5 |
| Новый UI-слой | `front/src/components/ui-shadcn/` (Tailwind + shadcn) |
| Общие хелперы фронта | `front/src/lib/`, `front/src/utils/` |
| API-клиент | `front/src/api/` — новых `fetch`-обёрток не заводим |
| Pydantic-схемы | `back/schemas/<домен>/` |
| ORM-модели | `back/models/` — новая модель идёт в существующий файл домена, не в новый |
| Бизнес-логика бэка | `back/services/` |

## 2. Shared Code

Логика, полезная больше чем одной фиче, живёт в общем слое (`components/ui/`, `lib/`,
`back/services/`), а не внутри папки фичи. Понадобилась вторая копия — значит, место было выбрано
неверно: переносим в общий слой, а не копируем.

## 3. Duplicate Detection

Заметили дублирование (бизнес-логика, сервисы, утилиты, хуки, компоненты, типы, API-обёртки) в коде,
**не относящемся к текущему эпику** — не рефакторим. Дописываем запись в
[`TECH_DEBT.md`](TECH_DEBT.md): дата, приоритет, файлы, описание, рекомендуемый рефакторинг.
Старые записи никогда не удаляем.

## 4. Current Epic Rule

Дубль внесён **текущим эпиком** — чиним сразу, до сдачи. Переиспользуем существующее или выносим
в общий модуль. Осознанно новое дублирование не вносим никогда.

## 5. Minimal Refactoring

Рефакторим только то, что напрямую относится к текущему эпику. Большие сторонние рефакторинги —
только по явному запросу.

## 6. Роадмапы — по одной странице

App-wide эпики к аудиту страницы не прицепляем. Общие компоненты строим общими, но внедряем только
на странице аудита; остальное — в [`BACKLOG/`](BACKLOG/README.md).

## Завершение эпика

Эпик не считается сделанным сразу после реализации. Перед закрытием — код-ревью по чек-листу:

- архитектура
- дублирование кода
- читаемость
- поддерживаемость
- нейминг
- нарушения SOLID
- производительность
- безопасность
- обработка ошибок
- краевые случаи

Найденное чиним, если это код текущего эпика; чужое — в [`TECH_DEBT.md`](TECH_DEBT.md).
Результат ревью дописываем секцией в [`CODE_REVIEW.md`](CODE_REVIEW.md).

## Верификация

Проверка = `npm run build` + `npm run lint` во `front/` и прогон `back/tests/` — не браузер.
Билд гоняем после каждой фазы, до отчёта пользователю.

# Перевод платежей в боевой режим (Stripe live)

Порядок здесь имеет значение: каждый следующий шаг проверяется предыдущим. Гейт —
`docker compose exec api python -m scripts.preflight`: пока он отвечает «Блокеров: N»,
включать live нельзя. Деплой и обновление кода — в [DEPLOY.md](../DEPLOY.md).

Денег в проекте два потока, и переключаются они ОДНОВРЕМЕННО, одним ключом платформы:

| Поток | Куда идут деньги | Код | Вебхук |
|---|---|---|---|
| Тариф Velora (подписка, комиссия) | на аккаунт платформы | `services/stripe_billing.py` | `/billing/webhook/stripe` |
| Касса студий (клиент платит за занятие/абонемент) | сразу на аккаунт студии (Connect, direct charges) | `services/stripe_connect.py` | `/checkout/webhook/stripe` |

---

## 0. Что уже сделано в коде

Ничего в коде переключать не надо — режим целиком определяется парой ключей в
`back/.env`. Отдельно стоит знать:

- **Publishable key отдаётся с бэкенда** (`routers/checkout/stripe_pay.py`), фронт его
  не вшивает — пересобирать `front` из-за смены ключей не нужно.
- **Каталог цен заводится сам** при первой оплате (`services/stripe_catalog.price_id`),
  ручной `sync` — только чтобы увидеть его заранее.
- **Preflight проверяет**: режим и парность ключей, раздельность секретов вебхуков,
  активацию аккаунта платформы, доступность Connect, **включённые способы оплаты**
  (`card` и `customer_balance`), статус Stripe Tax, **налоговые регистрации и своё DIČ
  на фактурах** (шаг 4), валюту, SMTP, юридические документы, каталог цен и **живость
  идентификаторов Stripe, лежащих в БД** (шаг 8).
- **Отмена подписки** — это тумблер «Автоматическое продление» в «Тариф и оплата →
  Способ оплаты»: выключение уводит подписку в `cancel_at_period_end`, доступ
  доигрывает оплаченный период. Ровно то, что обещают Условия §7. Карта для этого не
  нужна — иначе студия на IBAN не смогла бы ни отменить, ни вернуться.
- **Чего preflight НЕ видит** (только глазами в дашборде): галка «Listen to events on
  connected accounts» у каждого вебхука — из API этот флаг не читается, а перепутанный
  ломает целый денежный поток (шаг 7).

## 1. Публичный адрес CRM — до всего остального

Сейчас `WEB_APP_URL=http://localhost:5173`. На него Stripe возвращает владельца
после онбординга Connect и после оплаты тарифа; с него же берётся домен для
регистрации Apple/Google Pay. С localhost live не заработает — preflight это блокирует.

Нужно: домен вида `crm.jogaua.online`, отдающий фронт по https (второй hostname в
существующем cloudflared-туннеле на `web:80`, либо A-запись + `SITE_ADDRESS` в
корневом `.env`, тогда Caddy выпустит сертификат сам).

Затем в `back/.env`:

```ini
WEB_APP_URL=https://crm.jogaua.online
CORS_ORIGINS=https://crm.jogaua.online
```

`BACKEND_URL=https://api.jogaua.online` и `MINIAPP_URL` уже боевые — их не трогаем.

Тот же адрес добавить в Google Cloud Console (Authorized JavaScript origins) —
иначе перестанет работать вход через Google.

## 2. Активировать аккаунт платформы в live

Дашборд Stripe, переключатель **Test mode → выключить**, дальше «Activate payments»:

1. Юрлицо: тип бизнеса, IČO/DIČ, юридический адрес, представитель, документ.
   **Страна аккаунта потом не меняется** — выбирать ту, где зарегистрировано юрлицо
   (тестовый аккаунт сейчас CZ).
2. Банковский счёт для выплат (payouts).
3. **Settings → Business → Public details**: название, сайт, e-mail поддержки, логотип —
   это видит клиент на странице оплаты и в фактуре.
4. **Statement descriptor** — что увидит студия в выписке по карте. По умолчанию
   Stripe подставит имя юрлица; поставить узнаваемое (`VELORA`).

Проверка: `preflight` перестаёт писать «аккаунт платформы Stripe не активирован».

## 3. Включить Connect в live

**Connect → Get started**. Заполнить профиль платформы (что за сервис, кто
пользователи — SaaS для студий, платежи идут на счета студий).

- Тип аккаунтов: **Standard** (код создаёт именно их, `stripe_connect.create_account`).
- **Connect → Settings → Branding**: иконка, цвет, название — это видит владелец
  студии на анкете Stripe. Без брендинга анкета выглядит как чужая.
- Ответственность за возвраты/споры при direct charges лежит на подключённом
  аккаунте — дефолт менять не нужно.

Проверка: `preflight` не пишет «Stripe Connect недоступен».

## 4. Включить Stripe Tax в live

**Настройки Tax у test и live разные** — включённый в тесте не значит ничего. Все
счета платформы уходят с `automatic_tax`, поэтому без активного Tax **не выставится
ни один счёт** — ни за тариф, ни за комиссию.

**Tax → Settings**: адрес продавца, дефолтная налоговая категория (в коде уже
`txcd_10103001`, SaaS), поведение цен — `exclusive` (налог сверху).

**Tax → Registrations**: страны, в которых вы обязаны собирать НДС. Как минимум
страна юрлица; при продажах физлицам в другие страны ЕС — режим OSS. Это вопрос к
бухгалтеру, а не к коду: от регистраций зависит, какую ставку Stripe посчитает
студии, и она же поедет в её фактуру.

Без единой регистрации Stripe Tax не начисляет ничего — все счета уходят с нулём, и
недобор ложится на платформу. Это блокер preflight.

Одна регистрация (CZ) — рабочая конфигурация: студия из другой страны ЕС **без**
номера НДС получает **домашнюю ставку продавца**, а не ноль. Проверено вызовами
`tax.Calculation` на боевом ключе при единственной регистрации CZ:

| Плательщик | Итого с 39 € | Причина |
|---|---|---|
| CZ, без VAT ID | 47.19 (21 %) | `standard_rated` |
| PL / DE / SK, без VAT ID | 47.19 (21 %) | `standard_rated` |
| DE, с валидным VAT ID | 39.00 (0 %) | `reverse_charge` — так и должно быть |
| США | 39.00 (0 %) | `not_collecting` — вне охвата |

Ноль бывает только там, где он законен. Настоящий риск не в ставке, а в **пороге**:
домашняя ставка правомерна, пока продажи не-плательщикам НДС по ЕС не превысили
10 000 € в год; после порога нужен OSS и местная ставка каждой страны. Порог
отслеживает сам Stripe, решение — за бухгалтером. Preflight предупреждает отдельной
строкой.

### 4.1 Своё DIČ на фактурах — БЛОКЕР

**Settings → Invoices → Account tax IDs**: добавить свой налоговый номер.

Своё DIČ Stripe печатает только отсюда, и по умолчанию поле пустое. Без него
документ формально не фактура: §29 закона о НДС требует DIČ поставщика, и студия не
поставит по такому документу налог к вычету. Настройка аккаунтная — задаётся один раз
и применяется ко всем будущим фактурам, включая автосчета продлений.

Со стороны ПОКУПАТЕЛЯ на фактуру уезжают адрес и номер НДС из реквизитов плательщика
(«Тариф и оплата» → «Способ оплаты»), причём номер — только прошедший VIES. Поля
«ИНН/IČO» на фактуре нет: регистрационный номер компании в карточке студии
(`Studio.company_id`) — справочный и в Stripe не передаётся. Понадобится — это
`custom_fields` у Customer, отдельной задачей.

Проверка: `preflight` не пишет ни «Stripe Tax в статусе …», ни «на фактурах не
печатается ВАШ налоговый номер».

## 5. Включить оплату переводом (IBAN)

Тариф можно платить не только картой, но и переводом на коллекторский IBAN
(`BILLING_BANK_TRANSFER_COUNTRY=DE`, валюта EUR).

**Settings → Payments → Payment methods** → **Bank transfers / Customer balance** для
EUR. Это не переключатель: способ приходит в статусе **`unrequested`**, и его надо
ЗАПРОСИТЬ отдельно под каждую валюту («Visit the bank transfers settings page to
request them»). Stripe рассматривает заявку, и до одобрения способ недоступен.
Запрашивать нужно только EUR — счета за тариф идут в ней (`BILLING_CURRENCY`).

USD не нужен. Страна IBAN задаётся `BILLING_BANK_TRANSFER_COUNTRY` (по умолчанию DE)
и со страной аккаунта совпадать не обязана.

Пока способ не одобрен, кнопка «Оплатить переводом» отвечает 503 с внятным текстом
(`billing.bank_transfer_disabled`), а не общим «попробуйте ещё раз». Проверяет
preflight — `check_stripe_payment_methods` требует `on` у `card` и `customer_balance`.

## 6. Ключи → `back/.env`

**Developers → API keys** в **live**-режиме:

```ini
STRIPE_SECRET_KEY=sk_live_...
STRIPE_PUBLISHABLE_KEY=pk_live_...
```

Оба обязаны быть из одного режима — смешанная пара это блокер preflight
(«ключи из РАЗНЫХ режимов»). Секретный ключ показывается один раз: не сохранил —
выпускай новый (Roll key), старый при этом умирает.

Тестовые ключи не удалять: test-режим остаётся рабочей песочницей.

## 7. Два вебхука в live — с РАЗНЫМИ секретами

Вебхуки живут отдельно в каждом режиме: те, что настроены в test, в live не
появятся. **Developers → Webhooks → Add endpoint**, дважды.

### 7.1 Оплата тарифа

- URL: `https://api.jogaua.online/billing/webhook/stripe`
- События: `customer.subscription.created`, `customer.subscription.updated`,
  `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed`,
  `charge.refunded`, `setup_intent.succeeded`, `customer.tax_id.updated`
- `customer.tax_id.updated` — результат сверки VAT ID с VIES. **Без подписки на
  него студия с выдуманным DIČ платит без НДС бессрочно**: reverse charge Stripe
  даёт по формату номера сразу, а 21 % по несуществующему номеру налоговая
  вычтет из выручки платформы. Обработчик снимает такой номер и у Stripe, и в БД
  (`routers/billing/webhook._handle_tax_id`).
- **«Listen to events on connected accounts» — ВЫКЛ.** Тариф платят платформе;
  события подключённых аккаунтов обработчик отбрасывает.
- Signing secret → `STRIPE_BILLING_WEBHOOK_SECRET`

### 7.2 Касса студий

- URL: `https://api.jogaua.online/checkout/webhook/stripe`
- События: `checkout.session.completed`, `checkout.session.expired`,
  `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`,
  `charge.refunded`, `charge.dispute.created`, `charge.dispute.closed`
- **«Listen to events on connected accounts» — ВКЛ.** Без этого оплаты клиентов
  студий не проведутся: события приходят с аккаунта студии, а не платформы.
- Signing secret → `STRIPE_WEBHOOK_SECRET`

Одинаковый секрет на два эндпоинта — блокер preflight: он стирает границу между
деньгами платформы и деньгами студий.

### 7.3 Домены кошельков

**Settings → Payments → Payment method domains** → добавить домен CRM из шага 1.
Для подключённых аккаунтов домен регистрируется сам, на каждый клик «Подключить
Stripe» (`stripe_connect.register_payment_method_domain`) — но домен платформы надо
внести руками, иначе Apple/Google Pay не появятся в форме.

Регистрации мало: Apple проверяет домен по файлу
`/.well-known/apple-developer-merchantid-domain-association`. Он лежит в
[`front/public/.well-known/`](../front/public/.well-known/) и попадает в `dist` при
сборке — то есть раздаёт его Caddy вместе с фронтом, а НЕ бэкенд: домен CRM
(`jogaua.online`) обслуживает фронт, и запрос до api туда не доходит. Файл общий для
всех продавцов Stripe, менять его не нужно; обновлять — только если Stripe объявит
новый.

Проверка после деплоя фронта — ответ должен быть бинарным (hex), а не HTML:

```bash
curl -s https://<домен-CRM>/.well-known/apple-developer-merchantid-domain-association | head -c 40
```

SPA-фолбэк отдаёт на этот путь `index.html` с кодом 200, поэтому «200 OK» здесь
ничего не доказывает — смотреть надо именно содержимое.

## 8. Применить конфиг и вычистить тестовые ссылки из БД

```bash
docker compose up -d --force-recreate api     # именно так: restart не перечитывает .env
docker compose exec api python -m scripts.preflight
```

Preflight теперь спросит Stripe про каждый идентификатор из БД. **`cus_…` и `acct_…`
в test и live выглядят одинаково**, поэтому единственный способ отличить — спросить.
Если он пишет «в БД N ссылок на Stripe не существуют под текущим ключом» — это
тестовые объекты, и их надо снять:

```bash
docker compose exec -T db psql -U velora velora <<'SQL'
UPDATE studio_billing_plans SET stripe_customer_id = NULL, stripe_subscription_id = NULL;
UPDATE online_channels SET account_id = NULL WHERE channel_type = 'stripe';
DELETE FROM payment_cards;
UPDATE stripe_checkouts SET status = 'cancelled' WHERE status = 'pending';
SQL
```

Что это значит на практике:

- **Каждая студия заново проходит онбординг Stripe Connect** — тестовый `acct_…` в
  live не переносится, это ограничение Stripe. Пока не прошла, касса картой у неё
  не работает (наличные и офлайн — работают).
- Привязанные в тесте карты пропадают, подписку надо оформить заново.
- `studio_billing_plans.status` и `expires_at` — зеркало, их не трогаем: доступ у
  студии остаётся до конца ранее записанного периода, и это правильно.
- Строки в `billing_invoices` со старыми `stripe_invoice_id` остаются историей;
  ссылки на PDF у них умрут — при желании чистятся отдельно.

## 10. Гейт

```bash
docker compose exec api python -m scripts.preflight
```

Должно быть **«Блокеров нет»**. Предупреждение «Stripe в ТЕСТОВОМ режиме» обязано
исчезнуть — если оно осталось, `api` работает со старым окружением (см. `--force-recreate`).

`FX_CACHE_PATH` настраивать больше не нужно: курсы валют лежат в БД (`models.FxRate`,
UPSERT на каждый удачный поход к ЕЦБ) и переживают рестарт сами. Переменная и
проверка на неё удалены вместе с файловым кэшем.

## 11. Боевая проверка настоящими деньгами

Тестовыми картами live не проверяется — только реальной оплатой. Берём минимальные суммы.

1. **Тариф картой.** Оформить подписку «Старт» на 1 месяц своей картой. Проверить:
   счёт в Stripe оплачен, в CRM тариф активировался (это делает вебхук, не редирект),
   на почту пришла фактура с НДС, с регистрационным номером компании **и с вашим DIČ**
   (шаг 4.1 — без него документ не даёт студии права на вычет).
1a. **Отмена.** Выключить «Автоматическое продление» и убедиться, что в Stripe у
   подписки встал `cancel_at_period_end=true`, а в CRM подпись сменилась на «доступ
   до …». Включить обратно — флаг должен сняться. Это единственный путь отмены,
   обещанный Условиями, и ломается он молча.
2. **Тариф переводом.** Нажать «Оплатить переводом» — должны показаться IBAN и BIC
   (шаг 5). Сам перевод делать не обязательно, достаточно того, что реквизиты
   выдались.
3. **Касса студии.** Пройти «Подключить Stripe» до конца анкеты, дождаться
   `charges_enabled`, продать абонемент на минимальную сумму реальной картой.
   Проверить: деньги на балансе студии, а не платформы; продажа проведена в CRM;
   на процентном/комбо-тарифе доля платформы удержана как `application_fee`.
4. **Возврат.** Вернуть этот платёж из CRM. Проверить, что заявка ушла в `refunded`,
   а абонемент погашен.
5. **Мини-приложение.** Купить абонемент из Telegram — там другой путь оплаты
   (хостед-страница вместо встроенной формы).

Если что-то не сошлось — **Developers → Webhooks → выбрать эндпоинт → Attempts**:
там видно и код ответа, и тело. 400 = не сошлась подпись (перепутаны секреты);
событий вообще нет = не тот URL или выключены connected accounts.

## 12. Первую неделю

- **Developers → Events** и вкладка Attempts у обоих вебхуков: ретраи Stripe шлёт
  сутки, но молча упавший обработчик = непроведённая оплата.
- **Balance → Payouts**: первая выплата на банковский счёт идёт дольше обычного.
- `docker compose logs -f api | grep -i stripe` — весь денежный путь пишет в лог.
- Радар: **Radar → Rules** — дефолтных правил хватает, но пороги стоит посмотреть
  после первых реальных платежей.

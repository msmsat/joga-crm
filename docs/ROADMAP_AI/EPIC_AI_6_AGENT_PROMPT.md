Скопировать целиком в новый чат модели-исполнителя (Claude Code / другой агент

Ты — исполнитель одного конкретного плана в репозитории Velora CRM

## Прежде чем написать первую строку кода

1. Прочитай целиком: `CLAUDE.md` (правила проекта — они выше твоих привычек),
   `docs/ROADMAP_AI/EPIC_AI_6_BACKLOG.md` (план), `docs/ROADMAP_AI/ROADMAP.md`
   (контекст ветки AI), раздел «Velora AI» в `docs/TZ/STATUS.md`.
2. Прочитай в эпике разделы **«Точка старта»**, **«Решения эпика»** и
   **«Что эпику ЗАПРЕЩЕНО ломать»**. Эти три раздела действуют на всех 20
   задачах, а не только на первой.
3. Ничего не делай «заодно». План — единственный источник объёма работ.

## Цикл одной задачи — выполняй ровно в этом порядке

1. **Прочитай раздел задачи в эпике целиком**, включая «Простыми словами»,
   «Зачем», «Где», «Подводные камни» и «Готово, когда».
2. **Прочитай реальный код**, который будешь трогать, — все файлы из «Где» и
   всё, что они импортируют по делу. План писался 15.08.2026: если код с тех
   пор разошёлся с планом, **приоритет у кода**, а расхождение ты выносишь
   человеку вопросом (см. «Когда останавливаться немедленно»).
3. **Сделай задачу.** Только её. Не начинай следующую, даже если она на две
   строки и «логично сразу».
4. **Проверь результат** — именно теми командами, которые уместны:
   - бэкенд: `cd back` → `pytest tests/test_ai_chat.py tests/test_ai_tools.py
     tests/test_ai_action.py` (плюс новые файлы задачи), самопроверки модулей
     (`python -m services.ai_tools`, `python -m services.llm`);
   - фронт: `cd front` → `npm run build`, затем `npm run lint`, затем
     проверки-скрипты, если задача их добавила (`npm run check:uimap`,
     `npm run check:ai`);
   - в конце фазы — `cd back && pytest` целиком (прогон всей папки безопасен).
   Windows PowerShell: `&&` не работает, запускай команды по одной.
5. **Отчитайся коротко** (не пересказом плана):
   - что сделано одной фразой;
   - список изменённых и созданных файлов;
   - **дословный хвост вывода проверок** (последние строки pytest/build/lint);
   - что из «Готово, когда» выполнено, а что нет и почему.
6. **Спроси человека и остановись.** Обязательный шаг, пропускать его нельзя
   даже если задача тривиальная.

## Как спрашивать после каждой задачи

Задай вопрос интерактивным окном выбора — инструментом `AskUserQuestion`
(в Claude Code это он; в другом харнессе — аналогичный инструмент вопроса).
Если такого инструмента нет, напиши вопрос текстом и **остановись, не
продолжая работу**, пока не получишь ответ.

- Заголовок (header): `Задача N`
- Вопрос: `Задача N «<название из плана>» готова. Что дальше?`
- Варианты:
  1. **«Продолжаем»** — перехожу к задаче N+1 (рекомендованный вариант,
     ставь его первым).
  2. **«Проверяем»** — останавливаюсь и жду: человек смотрит результат сам.
     На этот ответ ты **ничего не меняешь в коде**, а перечисляешь, что именно
     стоит посмотреть глазами: какие экраны открыть, какой вопрос задать
     ассистенту, что должно произойти. Ждёшь следующей команды.
  3. **«Правим»** — что-то не так, жду замечаний и исправляю в рамках этой же
     задачи, потом снова задаю этот же вопрос.

Никогда не отвечай за человека и не предполагай, что он выбрал бы «Продолжаем».

## Когда останавливаться немедленно (не доделывая задачу)

Спроси человека тем же окном, если:

- **план противоречит коду** (файла нет, функция называется иначе, роль другая) —
  покажи расхождение и предложи вариант, но не переписывай план молча;
- задача требует **изменить чужие незакоммиченные правки** (проверь
  `git status` перед работой с `package.json`, `plans.py`, схемами биллинга);
- нужна **миграция Alembic** — перед `downgrade` заново проверь `alembic heads`
  (параллельная работа могла добавить голову за минуты);
- задача тратит **реальные деньги** (задача 19 гоняет живую модель, ≈ $0.60 за
  прогон) — предупреди до запуска;
- ты собираешься **поставить новую зависимость** — назови её и зачем.

## Запреты (нарушение = откат работы)

1. **Никаких `git commit`, `git push`, `git stash`, `git reset`,
   `git checkout -- <файл>`, `git restore`.** В этом репозитории такими
   командами уже дважды теряли работу. Правки оставляй в рабочей копии.
   Внешний процесс сам коммитит рабочую копию — если `git status` внезапно
   чистый, это нормально, ничего не «восстанавливай».
2. **Не запускай dev-сервер и браузер для проверки.** Верификация здесь —
   билд, линт, тесты и самопроверки модулей. Визуальную проверку делает
   человек по варианту «Проверяем».
3. **Не пиши свои кнопки, инпуты, модалки, тултипы, селекты** — только UI-кит
   `front/src/components/ui/` (§5 CLAUDE.md). Не хватает варианта — расширь
   компонент кита, не создавай локальную копию.
4. **Эмодзи как иконки запрещены** — только inline SVG. Это касается и оценок
   👍/👎 из задачи 18: в интерфейсе они рисуются иконками.
5. **Не выдумывай подписи кнопок, маршруты и названия блоков.** Всё, что
   попадает в карту интерфейса, берётся из кода и локалей
   (`front/src/locales/ru/*.json`). Ровно на этом эпик и построен: подписи
   «+ Сотрудник» в продукте не существует, а в старой карте она была.
6. **Не оставляй `// implement later`** и полуготовых веток. Задача либо
   сделана, либо остановлена вопросом.
7. **Не трогай контракты, перечисленные в «Что эпику ЗАПРЕЩЕНО ломать»**:
   сигнатуру `send_message`, роли сообщений в `AIChatMessage`, правило превью,
   непустой ответ, заглушку при пустом `LLM_API_KEY`, ролевой скоуп.
8. **Не делай задачи параллельно и не запускай сабагентов** без явной просьбы
   человека.

## Стиль работы

- Самое ленивое решение, которое действительно работает: сначала переиспользуй
  то, что в репозитории уже есть (паттерн `?client=`/`?tab=`, скрипты
  `front/scripts/check-*.mjs`, UI-кит, `_items()` в `ai_tools.py`), потом
  стандартную библиотеку, и только потом пиши новое.
- Комментарии — как в соседнем коде: по-русски, объясняют **почему**, а не
  что. Осознанные упрощения помечай `# ponytail: <потолок>; <когда менять>`.
- Файлы держи меньше 300 строк; выросло — дели на `hooks/` и `components/`.
- Меняешь UI (кнопка, вкладка, маршрут) — правь `back/services/ai_uimap.md`
  в том же шаге.

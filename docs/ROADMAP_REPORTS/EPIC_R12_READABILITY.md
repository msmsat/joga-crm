# EPIC R12 — Read-first: расшифровки под заголовками и сигнал рядом с графиком

**Цель:** владелец должен понимать блок, не открывая подсказку. Сейчас смысл
метрики спрятан в i-поповере: заголовок «Динамика» ничего не объясняет, а
расшифровка «Доля клиентов, пришедших повторно после первого визита» видна
только по клику. Плюс «Что требует внимания» лежит в подвале — сигнал читается
последним, хотя по спеке он стоит рядом с главным графиком.

**Спека:** «понятный заголовок + короткая расшифровка под ним + иконка i с
формулой» и «справа или внизу страницы — блок "Что делать"».
**Аудит:** пункты 1, 2 третьей волны (фронт, визуал — бэк не трогаем).
**Зависимости:** нет. Первый эпик волны — вся страница read-only, риск нулевой.
**Оценка: ~4:45.**

## Frontend Architecture

### Задача 1. `Reports/components/shared/CardHeading.tsx` (новый)

Один компонент вместо восьми копипаст-заголовков. Живёт в `shared/` Отчётов, а
не в ките: это композиция `InfoHint` + типографика конкретной страницы.

```tsx
export interface CardHeadingProps {
  title: string;
  description?: string;   // короткая расшифровка под заголовком
  formulaKey?: string;    // ключ formulas.* → InfoHint с формулой
  actions?: React.ReactNode;
}

export function CardHeading({ title, description, formulaKey, actions }: CardHeadingProps) {
  const { t } = useTranslation('reports');
  return (
    <div style={{ display: 'flex', alignItems: 'flex-start', justifyContent: 'space-between', gap: '12px', marginBottom: '20px' }}>
      <div style={{ display: 'flex', alignItems: 'center', gap: '8px', minWidth: 0 }}>
        <div style={{ minWidth: 0 }}>
          <h3 style={{ fontSize: '15px', fontWeight: 800, color: 'var(--text)', margin: 0, letterSpacing: '-0.2px' }}>{title}</h3>
          {description && (
            <p style={{ fontSize: '12px', lineHeight: 1.45, color: 'var(--text3)', margin: '3px 0 0', maxWidth: '52ch' }}>
              {description}
            </p>
          )}
        </div>
        {formulaKey && <InfoHint title={t(`formulas.${formulaKey}.title`)} text={t(`formulas.${formulaKey}.text`)} />}
      </div>
      {actions}
    </div>
  );
}
```

`ChartCard` худеет до обёртки `Card` + `CardHeading` (проп `subtitle`
переименовывается в `description` — единый словарь во всех блоках), остальные
7 мест заменяют свой `<h3>…</h3><InfoHint/>` вызовом `CardHeading`. **Итог по
диффу: удаляется больше строк, чем добавляется.**

Расшифровки по блокам (ключи `descriptions.*`):

| Блок | Заголовок | Расшифровка |
|---|---|---|
| `overview.revenueStructure` | Структура выручки | Из чего сложились деньги за период |
| `overview.clientDynamics` | Динамика клиентов | Сколько пришло впервые, вернулось и перестало ходить |
| `sales.chart` | Выручка и продажи | Сумма и число покупок по дням периода |
| `sales.byCategory` | Что покупают | Доля каждого продукта в выручке |
| `sales.byMethod` | Как платят | Распределение выручки по способам оплаты |
| `sales.buyerType` | Кто покупает | Сколько денег приносят новые клиенты, а сколько постоянные |
| `sales.products` | Продукты | Каждый продукт: сколько продано, на какую сумму и растёт ли |
| `clients.chart` | Новые и вернувшиеся | Сколько клиентов пришло впервые и сколько вернулось, по неделям |
| `clients.riskSegments` | Требуют внимания | Клиенты, которых можно потерять, если не написать сейчас |
| `clients.loyalSegments` | Опора студии | Те, кто ходит чаще всех, платит больше всех и приводит друзей |
| `team.trainers` | Тренеры | Сравнение по загрузке, выручке и возвращаемости клиентов |
| `schedule.heatmap` | Загрузка по дням и часам | Где расписание переполнено, а где стоит пустым |
| `schedule.topProfitable` / `topFilled` / `chronicLow` / `halls` | как сейчас | по одной строке на блок |

### Задача 4. `Reports/components/shared/MainWithInsights.tsx` (новый)

```tsx
// Сигнал стоит рядом с главным графиком, а не в подвале: владелец читает
// «что не так» одновременно с данными. 320px — минимум, при котором текст
// сигнала и кнопка действия живут в две строки без переносов слов.
export function MainWithInsights({ insights, children }: { insights: Insight[]; children: React.ReactNode }) {
  const side = insights.length > 0;
  return (
    <div style={{
      display: 'grid',
      gridTemplateColumns: side ? 'minmax(0,1fr) 320px' : 'minmax(0,1fr)',
      gap: '20px', marginBottom: '20px', alignItems: 'start',
    }}>
      {children}
      {side && <InsightsPanel insights={insights} variant="side" />}
    </div>
  );
}
```

Применяется на **Обзоре, Продажах, Клиентах** — там главный блок это график,
который спокойно живёт в 1fr. **Команда и Расписание не меняются**: их главный
блок — широкая таблица тренеров и тепловая карта на 7 колонок, сужать их на
320px нельзя; панель остаётся во всю ширину внизу (спека допускает «справа
**или** внизу»).

`InsightsPanel` получает `variant?: 'side' | 'full'` (по умолчанию `full` —
Команда и Расписание не трогаем):

- `side`: вертикальный стек, `whiteSpace: 'normal'`, `WebkitLineClamp: 3`
  вместо `nowrap`/`ellipsis`; кнопка действия под текстом на всю ширину;
  контейнер `position: sticky; top: 16px` — при скролле длинной вкладки сигнал
  остаётся в поле зрения;
- `full`: текущая горизонтальная раскладка байт в байт.

### Задача 5. i18n

Новый неймспейс верхнего уровня в `ru/reports.json` и `en/reports.json` (рядом
с `formulas`) — расшифровки не мешаются с формулами:

```jsonc
"descriptions": {
  "overview": {
    "metric": {
      "revenue": "Все деньги, поступившие в студию за период",
      "profit":  "Что осталось после расходов периода",
      "attendance": "Занятия, на которые клиенты действительно пришли",
      "new_clients": "Клиенты, зарегистрированные в этом периоде",
      "fill_rate": "Насколько заполнены занятия: занято мест из доступных"
    },
    "revenueStructure": "Из чего сложились деньги за период",
    "clientDynamics": "Сколько пришло впервые, вернулось и перестало ходить"
  },
  "sales": { "chart": "…", "byCategory": "…", "byMethod": "…", "buyerType": "…", "products": "…" },
  "clients": { "chart": "…", "riskSegments": "…", "loyalSegments": "…" },
  "team": { "trainers": "…" },
```

~24 новых ключа × 2 языка. Формулировки — бизнес-языком, как задал R9: без
SQL, без слов «join», «distinct», «агрегация».

## Styling & UI/UX

- Расшифровка: 12px, `var(--text3)`, `line-height 1.45`, `max-width: 52ch` —
  строка не растягивается на всю карточку и читается как подпись, а не как
  второй заголовок.
- Между заголовком и расшифровкой 3px: они читаются одним блоком.
- i-иконка остаётся на уровне **заголовка** (`alignItems: 'center'` внутреннего
  флекса), не съезжает к расшифровке.
- Сайдбар сигналов: та же `Card`, `padding 20`, `sticky top 16px`; карточка
  сигнала — вертикальная (точка + текст, кнопка под текстом во всю ширину).
- Цвета severity (`info`/`warning`/`critical`) не меняются.
- Тёмная тема: расшифровка на `var(--text3)` — токен уже темизирован.

## Edge Cases

| Ситуация | Поведение |
|---|---|
| `insights` пуст | Сайдбар не рендерится, `gridTemplateColumns` схлопывается в одну колонку — дыры 320px нет |
| Один сигнал | Сайдбар рендерится с одной карточкой, `sticky` работает |
| Длинный текст сигнала (en + число) | `line-clamp: 3` + `title`-атрибут с полным текстом |
| Узкий экран (<1280px) | `@media`: одна колонка, сигналы уходят под главный график (текущее поведение) |
| Ключ `descriptions.*` отсутствует | `t()` вернёт ключ — ловится линтом i18n; расшифровка опциональна, блок не падает |
| Блок без формулы (`formulaKey` не задан) | i-иконка не рендерится, заголовок и расшифровка на месте (нужно для будущих блоков) |
| Переключение метрики Обзора | Заголовок и расшифровка меняются вместе с графиком, высота карточки не прыгает (расшифровки одной длины ±1 строка) |
| Смена языка на en | Расшифровки короче русских — `max-width: 52ch` не даёт строке растянуться, вёрстка не едет |

## Definition of DONE

- У **каждого** графика и блока страницы: понятный заголовок, расшифровка одной
  строкой под ним, i-иконка с формулой. Проверка: скриншот каждой из 5 вкладок,
  ни одного блока без подписи.
- Тепловая карта имеет название и объяснение цвета.
- На Обзоре, Продажах и Клиентах «Что требует внимания» стоит справа от
  главного графика, текст сигнала виден целиком, кнопка действия работает.
- `InsightsPanel` в варианте `full` на Команде и Расписании выглядит как до
  эпика (регресс-скриншот).
- Ни одной новой копии заголовочной вёрстки: `grep -c "fontWeight: 800" Reports/`
  падает с 8+ до 1 (только `CardHeading`).
- Все строки через `t('reports:…')`, ru и en заполнены.
- `npm run build && npm run lint` зелёные.

# EPIC R16 — Профиль тренера: загрузка по времени суток и его расписание

**Цель:** закрыть последние два пункта спеки по вкладке Команда. Профиль тренера
обещает пять блоков — динамику выручки, загрузку **по дням и времени**, любимые
клиентами занятия, возврат клиентов и **его расписание**. Сделаны три: загрузка
есть только по дням недели, расписания в профиле нет вовсе. Из-за этого главный
инсайт вкладки не собирается: «у Анны высокая возвращаемость, но свободны
вечерние слоты» невозможно увидеть — вечер от утра в профиле не отличить.

**Спека:** «Профиль тренера в отчётах: динамика выручки; загрузка по дням и
времени; любимые клиентами занятия; возврат клиентов; **его расписание**».
**Аудит:** пункт 6 третьей волны.
**Зависимости:** R12 (`CardHeading` для новых блоков дровера). Технически
независим от R13–R15 — можно двигать по приоритету PO.
**Оценка: ~4:00.**

## Backend Architecture

### Схема — `back/schemas/analytics/reports.py`

```python
class TrainerHourLoadPoint(BaseSchema):
    hour: int
    lessons: int
    fill_pct: float


class TrainerDetailRead(BaseSchema):
    revenue_series: list[SeriesPoint]
    load_by_weekday: list[TrainerLoadPoint]
    load_by_hour: list[TrainerHourLoadPoint]     # новое поле
    top_lessons: list[TrainerTopLesson]
    return_rate_pct: float
    returned_clients: int
    total_clients: int
```

Отдельный класс, а не переименование `weekday` → `bucket`: `TrainerLoadPoint`
уже читает фронт (`TrainerDrawer.tsx:40`), ломать поле ради экономии одного
класса — плохой обмен.

### Задача 1 — `back/routers/analytics/team.py` (эндпоинт `:340`)

Копия блока `load_by_weekday` (`:391`) с заменой группировки:

```python
hour = func.extract("hour", Lesson.start_time).label("hour")
# Ось — рабочее окно SERIES_DAY_HOURS (6..23), как у часовых серий Обзора:
# при полной оси владелец видит именно пустые часы, а не отсутствие данных (R6).
```

- Условия — те же `lesson_conds(f, sid)` + `Lesson.teacher_id == id`, то есть
  фильтры и период вкладки применяются как ко всему остальному в дровере.
- `fill_pct` = `occupied_expr() / capacity_expr() * 100`, округление до 0.1 —
  один в один с `load_by_weekday`, чтобы цифры двух разрезов сходились.
- Пустые часы отдаём нулями через `fill_series` — фронт не додумывает ось.
- Сумма `lessons` по часам == сумма по дням недели (инвариант для теста).

### Задача 4 — тест `back/tests/test_analytics_team.py`

1. `sum(p.lessons for p in load_by_hour) == sum(p.lessons for p in load_by_weekday)`;
2. занятие в 19:00 → `load_by_hour[hour=19].lessons == 1`, соседние часы нули;
3. длина `load_by_hour` == длина `SERIES_DAY_HOURS` (полная ось, R6);
4. тренер без занятий → все `fill_pct = 0`, 200 без 500.

## Frontend Architecture

### Задача 2. `tabs/team/drawer/TrainerCharts.tsx`

Второй график получает переключатель разреза — тот же сегмент-контрол, что у
метрик Обзора и разрезов потерь (R14), новых паттернов не вводим:

```tsx
type LoadDim = 'weekday' | 'hour';
const [dim, setDim] = useState<LoadDim>('weekday');
// «По дням» отвечает «в какие дни он загружен», «По часам» — «утро или вечер»:
// это два разных управленческих вопроса, поэтому переключатель, а не два графика.
```

Данные для `hour` — `data.load_by_hour` из того же запроса
(`analyticsApi.getTrainerDetail`), второй запрос не нужен. Подпись оси — `19:00`
через существующий `fmtBucket(period, 'hour')`-стиль форматирования часа.
Заголовок и расшифровка блока меняются вместе с разрезом (механика R12, задача 3).

### Задача 3. `tabs/team/drawer/TrainerSchedule.tsx` (новый)

Расписание тренера за период отчёта — **без нового эндпоинта**: журнальный
`scheduleApi.getLessons({ date_from, date_to })` уже вызывается на Обзоре и
кэшируется по ключу `queryKeys.journalLessons(from, to)`; фильтр по тренеру —
на клиенте.

```tsx
// teacher_id фильтруем на клиенте: journal API параметра тренера не имеет
// (schedule.api.ts:5 — только date_from/date_to/hall_id), а ответ уже в кэше
// Query после Обзора. Заводить эндпоинт под список из 20 строк незачем.
const lessons = (all ?? [])
  .filter(l => l.teacher_id === trainer.trainer_id)
  .sort((a, b) => a.start_time.localeCompare(b.start_time));
```

Строка: дата и время · название · зал · заполненность `booked/total` · статус.
Название зала берётся из `scheduleApi.getHalls()` по тому же `queryKeys.halls`,
что уже загружен в `Reports.tsx:42` — из кэша, без запроса.

- Отменённые занятия (`status === 'cancelled'`) показываем перечёркнутыми, а не
  скрываем: «почему у тренера дыра в среду» — это ответ.
- Список длиннее 10 строк скроллится внутри блока (`max-height: 320px`,
  `overflow-y: auto`) — дровер не растёт бесконечно.
- Пусто → `EmptyState size="sm"`: «За этот период занятий нет».
- Блок встаёт последним в дровере, после ринга возвращаемости, с той же
  анимацией входа `fadeIn(0.16)`.

Кнопка «Открыть профиль» в `TrainerHero` (`:49`) остаётся: расписание в отчёте —
для чтения, редактирование живёт в Сотрудниках и Журнале.

## Styling & UI/UX

- Переключатель разреза — копия сегмент-контрола Обзора (`OverviewTab.tsx:226`),
  размер `sm`: в дровере он не должен перетягивать внимание с графика.
- Столбцы загрузки — `PEACH_LIGHT`, как во всех барах страницы; заполненность
  ≥90% — насыщенный `#F9A08B` (та же логика, что в тепловой карте).
- Строка расписания: 13px, время `tabular-nums`, зал — цветной кружок 8px цветом
  зала (цвет зала — тот же источник, что в Журнале), статус — капсула 10.5px.
- Отменённое занятие: `text-decoration: line-through`, `opacity: 0.55`.
- Скролл блока расписания — без своей полосы поверх контента: `overflow-y: auto`
  + `padding-right: 4px`.
- Тёмная тема — только токены, hex в разметке не появляется.

## Edge Cases

| Ситуация | Поведение |
|---|---|
| Тренер без занятий в периоде | Оба графика — нули по полной оси, расписание — EmptyState; дровер не пустой |
| Занятия только в 07:00 | Ось всё равно 6..23, столбец один — видно, что человек работает только утром |
| Занятие в 03:00 (вне окна 6..23) | В часовой разрез не попадает; в расписании присутствует — блоки не обязаны совпадать построчно, инвариант только по `Σ lessons` разрезов дня/часа |
| Период = 1 день | «По дням» — один столбец, «По часам» осмысленен; дефолт остаётся `weekday` |
| Период = год | Расписание может быть длинным — скролл + `max-height`, запрос тот же (журнальный API уже отдаёт диапазон) |
| Отменённые занятия | В расписании перечёркнуты; в загрузку не входят (`lesson_conds` их исключает) — расхождение объяснено расшифровкой блока |
| Занятие без зала (`hall_id = null`) | Кружок цвета не рисуем, зал — «—» |
| Активен фильтр по залу | Загрузка и расписание считаются под фильтром (единый `lesson_conds`) |
| Дровер открыт, период сменили в тулбаре | Query-ключ содержит `paramsKey` — дровер перезапрашивает и данные, и расписание без F5 |

## Definition of Done

- В профиле тренера пять блоков спеки: динамика выручки, загрузка **по дням и по
  часам** (переключатель), любимые занятия, возврат клиентов, **расписание**.

- Расписание тренера не делает нового запроса: в Network при открытии дровера
  после Обзора нет второго `GET /schedule/lessons`.
- Все строки через `t('reports:…')`, ru и en заполнены.

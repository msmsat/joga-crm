# Лимиты ИИ — 08.09.2026

Квота общая для всех пользователей одной студии; ограничивает CRM-ассистента в чате, верхней строке и SSE-потоке.

| Тариф | Запросов |
|---|---:|
| Пробный | 500 за весь пробный период |
| Фикс / комбо: 2 места | 1000 в месяц |
| Каждое дополнительное оплаченное место | +500 в месяц |
| Фикс / комбо: «Безлимит» | 10 000 в месяц |
| Процент | 1500 в месяц |
| ИИ-админ: Telegram, Instagram, WhatsApp | Без тарифной квоты запросов |

## Правила учета

- Платный период — календарный месяц UTC. Триал считается с `trial_started_at`; для legacy free_trial без даты используется вся история CRM-запросов. Оплата прекращает применение пробного лимита. На проценте устаревшие trial-поля игнорируются, как в существующем subscription gate.
- Места берутся из действующего оплаченного тарифа, а не из числа заполненных карточек сотрудников. Запланированный апгрейд сам по себе лимит не увеличивает.
- `AIUsage.surface=crm` и `billable=true` — один запрос. Дополнительные LLM-итерации/эскалации не расходуют новые запросы. Расходы мессенджеров и их сообщения исключены из квоты CRM.
- Доступ и текст проверяются до допуска. Под коротким PostgreSQL row lock тарифа проверяется остаток и сохраняется одна строка допуска. Первый ответ модели заполняет ту же строку фактическим usage; замок не удерживается во время сети.
- Принятый запрос учитывается даже при последующем сбое провайдера или закрытии потока. Такая строка может сохранить `model=pending`, стоимость 0 до получения фактического usage; это не выдуманная стоимость вызова. Локальная заглушка без настроенного провайдера квоту не расходует.
- Переход между платными тарифами не стирает расход текущего месяца; снижение лимита ниже использованного остатка блокирует новые запросы. Пробные запросы текущего месяца также входят в месячный расход после оплаты.
- HTTP 429 приходит до вызова модели при исчерпанной квоте. При гонке за последним запросом проходит только один допуск.
- Нет тарифа / неизвестный тариф — лимит 0; проверки подписки и ролей остаются отдельным существующим уровнем доступа.
- Старый общий `AI_TRIAL_LIMIT=150` больше не читается. Внутренний ориентир себестоимости каталога не ограничивает обещанное число запросов. Фактические расходы продолжают записываться.
- ИИ-админ не ограничивается этим механизмом. Существующие настройки каналов, расписание ответов, антиспам отдельного отправителя и технические rate limits сохраняются.

## Реализация и проверки

- Каталог цифр: `back/routers/billing/plans.py`.
- Правила/атомарный допуск: `back/services/ai_quota.py`.
- JSON и SSE: `back/routers/ai/chat.py`; статус: `back/routers/ai/settings.py`.
- Учет фактического расхода: `back/services/ai_usage.py`, `back/services/assistant.py`.
- ИИ-админ: `back/services/client_agent.py`.
- UI: `front/src/pages/dashboard/AI/components/LeftPanel.tsx`, словари пяти языков.
- PostgreSQL-тесты: `back/tests/test_ai_quota.py`; блокировка до модели: `back/tests/test_ai_agent.py`.

Схема БД не меняется, миграция не требуется. Изменения вступают в силу после загрузки обновленного backend; для новых подписей нужен обновленный frontend.

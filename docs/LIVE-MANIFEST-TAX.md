перечисленного не выполнено.** Выполнение начинается только после ответа владельца
ровно такой строкой:

```

```

Подтверждение действует только на операции из этого списка. Любое изменение
манифеста требует нового идентификатора и нового подтверждения.

| `sub_1U3O1B…`, `sub_1U3O7H…` | Обе `canceled`. Новых счетов не создают, значит и комиссии тоже. Правка флага на мёртвом объекте не даёт ничего, а лишнее событие и риск — даёт |

## 3. Порядок выполнения

1. Прогнать полный тестовый набор и `preflight` на staging.
2. Убедиться, что на момент окна нет запланированной финализации счёта подписки —
   сегодня это выполняется автоматически: живых подписок нет вовсе.
3. Завести Tax Rate: `python -m scripts.sync_tax_rates --apply`.
4. Выставить переменные окружения (шаг 1 таблицы) **без** `BILLING_TAX_MIGRATE_EXISTING`.
5. Выкатить код и применить миграцию БД.
6. `python -m scripts.preflight` — блокеров быть не должно.
7. Владелец выключает automatic tax в Dashboard (раздел 4 ниже).
8. `python -m scripts.migrate_tax_mode` — dry-run. Ожидается «подписок к переводу: 0».
9. `--apply` **не запускать**: переводить нечего.
10. Повторно прочитать изменённые объекты и сверить с манифестом.
11. Убедиться, что не появилось новых invoice, proration, charge, credit note или
    балансовых операций.

**Ожидаемое время:** 20–30 минут. **Необратимо:** ничего, кроме созданного Tax Rate
(его можно только архивировать).

## 4. Что делает владелец руками

Мне Dashboard недоступен — эти шаги может выполнить только владелец.

### Можно сделать сейчас безопасно

**А. Узнать фактические тарифы аккаунта** (нужно для честной таблицы комиссий).

* Ссылка: `https://dashboard.stripe.com/acct_1TyL8R1PBkRXkxBR/settings/plans-and-fees/plans`
* Прислать мне текстом или скриншотом строки для: Payments (карты ЕЭЗ / премиальные /
  международные), Billing, Invoicing, Tax, Connect, споры.
* **Ключи не открывать и не присылать.** Раздел Developers → API keys для этого не нужен.

**Б. Проверить, включён ли automatic tax для Dashboard-объектов** (пока только посмотреть).

* Ссылка: `https://dashboard.stripe.com/acct_1TyL8R1PBkRXkxBR/settings/tax/integrations`
* Найти переключатель вида «Use automatic tax» / «Automatically calculate tax».
* Сейчас: скорее всего **включён**. Прислать текущее значение.
* На этом шаге **ничего не переключать**.

### Только после подтверждения LIVE-манифеста

**В. Выключить automatic tax для Dashboard-объектов.**

* Та же ссылка: `.../settings/tax/integrations`
* Переключатель «Use automatic tax» → **выключить**.
* Сохранить (кнопка Save, если появится).
* **Побочный эффект:** счета и Payment Links, созданные вручную из Dashboard,
  перестанут считать налог автоматически. Для них придётся выбирать ручную ставку в
  интерфейсе. Объекты, созданные нашим кодом, этой настройкой не управляются.
* **Не нажимать** ничего в разделах Registrations и Settings → налоговые регистрации
  не трогаем.
* **Проверка:** создать в Dashboard черновик счёта и убедиться, что налог не
  подставляется сам и предлагается выбрать ставку. Черновик затем удалить —
  за неоплаченный черновик комиссии нет.

### Не трогать

* Tax → Registrations (чешская регистрация `small_seller`).
* Developers → API keys.
* Обе отменённые подписки.
* Оба погашенных счёта.
* Settings → Invoices → Account tax IDs (собственное DIČ).

## 5. Откат

Безопасный откат — **остановить выставление счетов**, а не вернуть платный расчёт.

1. Убрать `BILLING_TAX_MODE=manual` → новые документы снова считает Stripe Tax
   (платно). Делать только при явной необходимости.
2. Быстрее и дешевле: оставить ручной режим и не выставлять счета, пока причина не
   найдена — при нерешённом налоге код и так не финализирует документы сам.
3. Миграция БД `d4a91c6b7e58` обратима (`alembic downgrade`), но откатывать её не
   нужно: колонки nullable и ни на что не влияют.
4. Созданный Tax Rate архивируется (`active=false`), удалить нельзя.
5. Переключатель Dashboard возвращается тем же тумблером.

## 6. Проверка после выполнения

* `stripe.Subscription.list` — `automatic_tax` у любой новой подписки `false`.
* `stripe.Invoice.list` — у нового счёта `automatic_tax.enabled=false`, налог посчитан
  нашей ставкой, ставка приложена ровно один раз.
* `BalanceTransaction.list`, `type=stripe_fee` — не появилось `Automatic Taxes`,
  `Tax Api Calculation`, `Tax Api Transaction`. **Смотреть не раньше чем через сутки
  после первого реального счёта**: списание приходит на следующий день и датируется
  днём события. Искусственный live-счёт ради проверки не создавать.
* Dashboard → Balances → All activity — те же две строки.

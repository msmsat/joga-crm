Скопировать целиком в новую сессию ИИ, работающую в этом репозитории.

---

Реализуй спеку `docs/superpowers/specs/2026-08-20-client-agent-booking-design.md`.
Прочитай её целиком до первой правки — она источник истины, этот текст лишь
дорожная карта и список граблей.

Коротко: клиентский агент в мессенджерах (`back/services/client_agent.py`) умеет
сейчас только четыре инструмента чтения. Нужно довести его до 12 — добавить журнал
с поиском, тренеров, абонементы, личные данные клиента — и научить записывать на
занятие, отменять запись и продавать абонемент. В Telegram запись подтверждается
нажатием inline-кнопки, в WhatsApp выполняется сразу, в Instagram недоступна.

## Правила репозитория, которые нельзя нарушить

1. **Никаких `git commit`, `git push`, `git stash`, `git checkout --`, `git reset`.**
   В репозитории параллельно работает другой человек с незакоммиченными правками;
   в этом проекте такие команды уже дважды уничтожали чужую работу.
2. **Файлы правь инструментом Edit, а не через PowerShell.** `Get-Content | Set-Content`
   в этом окружении двойно кодирует кириллицу и портит русские комментарии
   безвозвратно.
3. **Комментарии на русском**, в стиле соседнего кода: объясняют «почему так»,
   а не «что делает строка». Посмотри `client_agent.py` — держи ту же плотность.
4. **Файл больше 300 строк — раздели.** Поэтому инструменты выносятся в новый
   `back/services/client_agent_tools.py`.
5. **Не оставляй `# TODO` и заглушек.** Не успеваешь — скажи, что не сделал.
6. Эмодзи запрещены в интерфейсе CRM, но **в чате с клиентом студии уместны** —
   это сообщения живому человеку, а не элементы админки.

## Грабли, каждая стоила бы тебе часа

1. **`@limiter.limit` на функциях мини-приложения.** Декоратор требует настоящий
   `Request` и считает лимит по IP, которого у фоновой задачи нет. Зови через
   `.__wrapped__(request=None, ...)`. Приём уже применён в `client_agent._call`
   для `public_services` — сделай так же и не изобретай обход.

2. **`client` НИКОГДА не приходит из аргументов модели.** Он берётся из
   `identify()` по идентификатору канала. Это не стилистика, а единственное, что
   мешает постороннему написать «покажи абонемент Анны Петровой». Инструмент,
   принимающий `client_id` параметром, — ошибка проверки, а не деталь.

3. **`create_reservation` требует `spot_number`** — номер коврика, который в
   приложении выбирают на схеме зала. Агент выбирает первое свободное место сам:
   в чате схемы нет.

4. **Ошибки `create_reservation` — уже готовый текст для клиента** («Ваш абонемент
   действует до … и это занятие уже не покрывает»). Показывай их как есть, не
   переписывай и не проси модель их пересказать.

5. **Telegram callback:**
   - `callback_data` — максимум 64 байта, поэтому `"book:{lesson_id}"`;
   - `answerCallbackQuery` обязателен, иначе у клиента вечно крутится часик;
   - вебхук обязан отвечать 200 **всегда** — на 4xx/5xx Telegram ретраит апдейт,
     и человек получает вторую бронь;
   - тип `callback_query` уже разрешён у бота, отдельный `setWebhook` не нужен;
   - ветка нажатия идёт **мимо модели**: это функция от `lesson_id`.

6. **Фоновая задача открывает свою сессию БД.** `get_db` отдаёт сессию через
   `yield`, и FastAPI закрывает её на выходе из запроса — раньше, чем корутина
   дойдёт до первого обращения к базе. Смотри `_agent_reply_task`.

7. **`llm.chat(..., think=False)` у этого агента.** Модель уровня клиента не
   должна размышлять: замерено 360–430 токенов раздумий на 180 символов ответа,
   это лишние секунды в чате. Не потеряй параметр при рефакторинге.

8. **Тестовые заглушки модели.** `conftest.py` подменяет `llm.chat` — реальных
   вызовов в тестах быть не должно. Добавляешь параметр в `llm.chat` — обнови
   сигнатуру `_ScriptedLLM._chat` в `tests/test_client_agent.py`, иначе прогон
   упадёт не там, где ошибка.

9. **`test_ai_injection.py` ужесточается, а не удаляется.** Сейчас он утверждает
   «изменяющих инструментов нет вовсе». Должен утверждать «изменяющих ровно
   `{book_lesson, cancel_booking, buy_subscription}`, и ни одного у неопознанного
   отправителя». Если этот тест станет слабее — работа сделана неправильно.

## Порядок работы

1. Вынеси существующие инструменты в `client_agent_tools.py`, прогони тесты —
   зелено. Только потом добавляй новые: так падение сразу покажет, чьё оно.
2. Инструменты чтения: журнал с поиском, тренеры, услуги, пакеты, личные четыре.
3. Гейт по каналу и опознанию: Instagram не получает ни личных, ни изменяющих.
4. Изменяющие инструменты + ветка `callback_query` в вебхуке.
5. `_RULES` на английский. Правило про язык ответа остаётся первым.
6. Тесты из §9 спеки.

## Как проверить, что готово

```bash
cd back
python -m pytest -q                          # сейчас 824 passed, должно остаться зелёным
python -m services.client_agent              # самопроверка модуля
python -m services.client_agent_tools        # самопроверка нового модуля — напиши её
python -m routers.booking.telegram_webhook   # самопроверка вебхука
python -m scripts.preflight                  # блокеров быть не должно
```

На Windows перед запуском самопроверок ставь `PYTHONIOENCODING=utf-8`, иначе
консоль падает на эмодзи в приветствии бота.

У каждого нетривиального куска — самопроверка `if __name__ == "__main__"` с
`assert`, как в существующих модулях. Для сборки клавиатуры и разбора
`callback_data` она обязательна: это чистые функции, тест на них ничего не стоит.

Живую проверку диалога делай отдельным скриптом во временной папке, а не тестом:
он тратит настоящие деньги на модель. В репозиторий такой скрипт не клади.

## Чего НЕ делать

- Не давать агенту инструменты из `services/ai_tools.py` — это CRM-функции с
  доступом к выручке и чужим клиентам, они защищены ролями сотрудников.
- Не добавлять нативные платежи Telegram — решение и причины в §6 спеки.
- Не заводить инструменты «про запас»: каждый расширяет поверхность атаки и
  замедляет выбор модели.
- Не трогать `services/ai_uimap.md` — карта интерфейса CRM к боту отношения не
  имеет.

# Скидка на первое занятие и оплата при индивидуальной записи

Дата: 2026-09-26. Статус: утверждено владельцем продукта («идём А+А, сделай всё»).

## Задача

1. **Первое занятие со скидкой в процентах.** Сейчас есть только «Первое занятие
   бесплатно» (тумблер в «Онлайн-запись → Основные настройки»). Студии нужно
   давать не только подарок, но и скидку: −50 %, −30 %. Настройка — на странице
   «Лояльность» (вкл/выкл + процент); в «Онлайн-записи» тумблер остаётся.
2. **Оплата на последнем шаге индивидуальной записи в Журнале.** Сколько платить,
   ваучер (подарочный сертификат), скидка первого занятия с выключателем,
   промокод. Оплата — только наличные, сразу в Финансы.

## Решения, принятые владельцем

| Вопрос | Решение |
|---|---|
| Где считать процент | В едином движке цены `services/pricing.resolve_price` (вариант А) |
| Как платит шаг оплаты | Запись и оплата — одна транзакция на сервере (вариант А) |
| Где блок оплаты | Во всех трёх окнах индивидуальной записи: пошаговый мастер (телефон, карточка клиента), окно кнопки «Индивидуально», окно у клетки сетки |
| Способ оплаты | Только наличные, сразу в Финансы. Способ не спрашиваем |
| Тумблер первого занятия | В обоих местах: «Онлайн-запись» — вкл/выкл, «Лояльность» — вкл/выкл и процент. Хранение одно |
| Скидка на шаге оплаты | Ставится сама, если положена; администратор может выключить её для этой записи |
| «Ваучер» | Подарочный сертификат из «Лояльности» (другого ваучера в продукте нет) |

## Данные

Две колонки, новых таблиц нет. Миграция `c0e4a2d9f1b7`-подобная (id — `secrets.token_hex(6)`).

| Таблица | Колонка | Смысл |
|---|---|---|
| `studio_booking_settings` | `trial_discount_percent` SMALLINT NOT NULL DEFAULT 100, CHECK 1..100 | Процент скидки первого занятия. Вкл/выкл — прежний `trial_lesson_free` |
| `reservations` | `trial_discount_percent` SMALLINT NULL, CHECK NULL или 1..100 | Процент, ОБЕЩАННЫЙ при записи. Заполнен ⇔ `is_trial` |

Существующие пробные брони получают 100 (бэкфилл в миграции). `is_trial` теперь
значит «первое занятие клиента со скидкой первого занятия»; 100 % — прежний подарок.

Зачем процент на брони: клиент записался в мини-приложении на следующую неделю
со скидкой 50 %, потом владелец поменял процент или выключил программу. Платит
клиент то, что ему показали при записи, — касса пересчитывает цену заново
(`perform_pay` → `_quote`) и без снимка взяла бы новую.

## Расчёт

`resolve_price(db, studio_id, client_id, base_price, promo=None, *, first_lesson_percent=None)`
получает ещё одного кандидата — `first_lesson` (процент от базовой цены). Правило
прежнее: самая выгодная клиенту скидка, без стека (если студийная скидка не
`stackable`). `ResolvedPrice.first_lesson_discount_applied` — сколько сняла именно она.
Ничего не гасит (`mark_used`): право на первое занятие гасится самой бронью.

Кто и когда передаёт процент:

| Путь | Откуда процент |
|---|---|
| Запись (`booking.resolve_funding`) | Клиенту положено первое занятие (`trial_applies`) и выключатель не снят → `rules.trial_discount_percent` |
| Касса за занятие (`_get_client_package`, `product_type="lesson"`) | Снимок на брони клиента на этом занятии |
| Оплата брони картой (`booking_payment.pay_link`) | Снимок на брони |
| Перенос к мастеру с другой ценой (`resource_reschedule._repriced`) | Снимок на брони |

`resolve_funding`:
1. абонемент покрывает — `SUBSCRIPTION` (как сейчас, первого занятия нет);
2. положено первое занятие и процент 100 — `TRIAL` (как сейчас: бесплатно, без долга);
3. цена 0 — `FREE`;
4. иначе — `client_price(first_lesson_percent=…)` → `PAY` с ценой клиента (0 → `FREE`).

Бронь получает `is_trial=True` и `trial_discount_percent` всегда, когда первое
занятие было положено и не выключено (пп. 2–4). Долг (`open_debt`) не заводится
только у бесплатного первого занятия (процент 100).

«Предоплата при записи» в мини-приложении: частичная скидка — это `PAY`, и гейт
действует как у любого платного занятия (платить картой). Бесплатное — гейт
пропускает, как и раньше.

## Выключатель на шаге оплаты

`CrmResourceQuoteRequest.first_lesson: bool = True` (только CRM; клиентская схема
его не знает). `False` → `resolve_coverage(allow_trial=False)`: ни подарка, ни
скидки, `is_trial=False`. Следующей записи первое занятие уже не положено — у
клиента появилась бронь. Снимок условий хранит эхо флага (`first_lesson`) и
`first_lesson_offered` (клиенту положено первое занятие, абонемента нет) — по нему
окно рисует выключатель и в выключенном состоянии.

## Предпросмотр оплаты и подтверждение с наличными

- `POST /schedule/booking-quotes/{quote_id}/payment-preview` `{promo_code?, certificate_code?}` —
  только чтение. Считает тем же `_quote`, что касса: скидки → сертификат → итог.
  Возвращает базовую цену, строки скидок по видам, валидность промокода (и
  «не суммируется — действует выгоднее»), номинал и списание ваучера или его
  ошибку, итог наличными. Покрыто абонементом / бесплатно — итог 0.
- `POST /schedule/bookings` принимает `payment: {promo_code?, certificate_code?, expected_total}`.
  Бронь создаётся как раньше, затем в той же транзакции `perform_pay` гасит долг
  наличными (доход в Финансы, комиссия, баллы, лента событий, сертификат,
  промокод). Итог разошёлся с `expected_total`, ваучер уже погашен, промокод
  умер — откатывается ВСЁ, брони нет, окно показывает причину.
- Без `payment` поведение прежнее (долг «оплата на месте»). Так записывают
  ассистент и старые клиенты API.

## Лояльность

- `GET/PATCH /loyalty/first-lesson` `{is_enabled, discount_percent}` — те же
  колонки `studio_booking_settings`, одним писателем с `PATCH /booking/settings`
  (замок студии, рост `booking_config_version` при изменении).
- Карточка «Первое занятие» в сетке программ, счётчик — первые занятия (брони
  `is_trial`, не отменённые). Дровер: процент 1–100 с быстрыми вариантами,
  пояснение про «не суммируется» и про тумблер в «Онлайн-записи».
- Ассистент: `get_loyalty_programs` отдаёт `first_lesson`; PATCH — `UI_ONLY`
  (как остальные настройки программ); `open_page(loyalty, tab=first_lesson)`.

## Поверхности

- **Журнал.** Блок «Оплата» — общий компонент для трёх окон; кнопка подтверждения
  называет сумму («Записать и принять 500 Kč»). Бейдж брони: «Пробное» /
  «Пробное · −50 %».
- **Онлайн-запись.** Тумблер переименован в «Скидка на первое занятие»; подпись
  называет текущий процент и где он меняется.
- **Мини-приложение.** `trial_available` по-прежнему значит «бесплатно» (старые
  сборки не покажут «Бесплатно» за −50 %). Новые поля `first_lesson_discount`
  (1–99) и `first_lesson_price_str` — строка цены «250 Kč · −50 %».

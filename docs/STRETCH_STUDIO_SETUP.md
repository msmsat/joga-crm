# Настройка тестовой студии «Стретч»

Этот пресет работает только со студией **17**, активным владельцем **6**, email
**sadomat31@gmail.com**. Студия **16 / tokarmaria1106@gmail.com** не изменяется.
Клиентов, оплат и посещений настройка не создаёт. Индивидуальные занятия
назначаются вручную на согласованное время, по одному человеку.

## Что создаётся

- Филиал «Основна студія», если филиалов нет; единственный существующий используется.
  При нескольких филиалах настройка останавливается для явного выбора.
- Зал «Зал стретчингу», 10 мест. Адрес остаётся пустым: добавьте настоящий в каталоге.
- Категория «Стретчинг»: «Здорова спина», «Розкішні шпагати», «Спина + шпагат».
  Каждое занятие длится 60 минут, 10 мест, 450 Kč. Первое групповое — 250 Kč.
- Категория «Індивідуальні заняття»: «Індивідуальне тренування», 60 минут,
  одно место, 1000 Kč. Пробная групповая скидка к нему не применяется.
- Групповые абонементы: 4 / 1600 / 30 дней; 8+1 / 2800 / 30;
  12+1 / 4000 / 60; 16+2 / 5100 / 60; 24+3 / 7300 / 90.
  Подарочные посещения уже входят в остаток, отдельный бонус их не дублирует.
- Индивидуальные: 1 / 1000; 4 / 3600; 8 / 7200; 10 / 9000; 12 / 10800.
  Все действуют 30 дней и подходят только к индивидуальной услуге.
- Заморозка: суммарно до 14 дней на абонемент; активный срок продлевается
  на использованные местные календарные дни. Автоматическое завершение каждые
  пять минут. Уже назначенные записи нужно предварительно перенести/отменить.
- Продление: 10% в день окончания предыдущего абонемента в часовом поясе Праги,
  один раз на предыдущий продукт, только для того же набора услуг.
  Автоматического списания с карты или депозита нет.

| День | Время | Занятие |
|---|---|---|
| Понедельник, среда, пятница | 09:00 | Здорова спина |
| Понедельник, среда, пятница | 10:30 | Спина + шпагат |
| Понедельник, среда, пятница | 14:00 | Спина + шпагат |
| Понедельник, среда, пятница | 16:00 | Здорова спина |
| Понедельник, среда, пятница | 17:00 | Розкішні шпагати |
| Суббота | 10:00 | Здорова спина |
| Суббота | 14:00 | Спина + шпагат |

Всего **17 недельных правил**. Они постоянно хранятся в базе. API при запуске
и далее каждый час создаёт обычные занятия в журнале на следующие **30 дней**.
Каждая неделя повторяется, после перевода часов сохраняется местное время Праги.
Для занятия действует обычный минимальный срок создания — три часа до начала.
Отменённое, удалённое или перенесённое вручную занятие не восстанавливается.
Два процесса защищены блокировкой студии и уникальной парой «правило + дата».
При конфликте времени ничего не переносится: ошибка попадает в лог, следующий
проход повторит попытку после устранения причины.

Повторное применение пресета сохраняет созданные ID и ручные изменения.
Редактирование одного занятия в журнале меняет только его. Недельные правила
хранятся отдельно в `recurring_lesson_templates`; изменение расписания целиком
требует правки правил, а не ручного перетаскивания всех будущих занятий.
Если ранее созданный объект удалили, повторная настройка требует проверки,
вместо создания второго объекта с новым ID. Предварительный отчёт показывает
существующие и предлагаемые рабочие часы студии, филиала и тренера.

## Где выполнять команды

Все команды ниже — **Linux SSH Google Cloud**, приглашение
`cartoonlvl2@velora-eu:~$`. Это не Windows PowerShell.

### 1. Обновить код

Доступны два пути. Если изменения уже опубликованы вами в Git:

```bash
cd "$HOME/joga-crm" &&
git status --short &&
bash ./backup.sh &&
git pull --ff-only &&
docker compose up -d --build api worker web &&
docker compose exec -T api alembic current
```

Ожидаемая миграция: `c74d80ab316e (head)`. Пока изменения только на ноутбуке,
`git pull` их не скачает. Для такого случая подготовлен архив
`joga-stretch-setup.zip`: в SSH нажмите **Upload file / Загрузить файл**
(значок шестерёнки или меню SSH), выберите этот архив на ноутбуке и дождитесь
завершения. Он должен оказаться в `/home/cartoonlvl2/`.

Перед установкой сделайте резервную копию:

```bash
cd "$HOME/joga-crm" && bash ./backup.sh
```

Проверьте SHA-256 архива по значению из сообщения со сборкой. Затем:

```bash
python3 -m zipfile -t "$HOME/joga-stretch-setup.zip" &&
python3 -m zipfile -e "$HOME/joga-stretch-setup.zip" "$HOME/joga-stretch-setup" &&
python3 "$HOME/joga-stretch-setup/install.py" --project "$HOME/joga-crm" --check &&
python3 "$HOME/joga-stretch-setup/install.py" --project "$HOME/joga-crm" &&
cd "$HOME/joga-crm" &&
docker compose up -d --build api worker web &&
docker compose exec -T api alembic current
```

Установщик проверяет все файлы до замены, сохраняет прежний код в отдельную
папку, не меняет `.env`, данные и фотографии. Если файл отличается от ожидаемой
версии, установка останавливается. Не применяйте обход с принудительной заменой:
сохраните вывод и сравните версию кода. Установка кода сама студию не заполняет.
Изменения из архива остаются локальными серверными правками до публикации через Git.

### 2. Предварительная проверка

```bash
cd "$HOME/joga-crm" &&
docker compose exec -T api python -m scripts.setup_stretch_studio \
  --owner-email sadomat31@gmail.com \
  --studio-id 17 \
  --report /app/uploads/stretch/preview.json &&
docker compose exec -T api cat /app/uploads/stretch/preview.json
```

Это пробная транзакция с откатом: услуги и занятия ещё не сохранены.
ID в предварительном отчёте временные; последовательности PostgreSQL могут
пропускать эти номера после отката. Это обычное поведение базы.
Проверьте `ready: true`, `complete: false`, владельца 6, студию 17,
`services: 4`, `weekly_templates: 17`, `booking_window_days: 30` и отсутствие
`schedule.conflicts`. Просмотрите цены, пакеты и изменение рабочих часов.

### 3. Применить

После проверки отчёта скопируйте весь блок:

```bash
cd "$HOME/joga-crm" &&
docker compose exec -T api python - <<'PY'
import json
from pathlib import Path
r=json.loads(Path('/app/uploads/stretch/preview.json').read_text(encoding='utf-8'))
assert (r.get('ready') is True and r.get('studio_id') == 17 and r.get('owner_id') == 6
        and r.get('services') == 4 and r.get('weekly_templates') == 17
        and r.get('booking_window_days') == 30 and not r.get('schedule',{}).get('conflicts'))
print('Предварительная проверка тестовой студии пройдена')
PY
if [ "$?" -eq 0 ]; then
  docker compose exec -T api python -m scripts.setup_stretch_studio \
    --owner-email sadomat31@gmail.com \
    --studio-id 17 \
    --apply \
    --report /app/uploads/stretch/applied.json
fi
```

Применение заново проверяет актуальную базу под блокировкой. Любой конфликт
откатывает всю настройку; старый предварительный отчёт не обходит эту защиту.

при старте он догоняет следующий 30-дневный период; прошлые занятия не создаёт.

## Оплата и Stripe

Наличные принимаются обычной кассой CRM: покупка абонемента создаёт продукт
клиента и доход в Финансах. Скидка продления применяется тем же расчётом,
что и в Stripe; незавершённая платёжная форма её не расходует.
Подтверждение Stripe учитывает сохранённый день скидки даже после полуночи,
повторный вебхук не проводит вторую оплату. Реальную карту в тестах не списывали.

Для онлайн-оплаты владелец целевой студии должен пройти собственное подключение
Stripe через существующие настройки CRM. Установщик не создаёт аккаунт Stripe,
не копирует ключи и не включает автоматические списания. До подключения
доступна запись с оплатой на месте; online purchase зависит от подключения.

## Проверки разработки

Новые сценарии проверяются на временной SQLite: расписание, защита от дублей,
Прага/DST, ручные изменения, откат настройки, пробная цена, заморозка,
очередь продуктов, продление, касса и обработчик Stripe без сети.
Миграция проверяется upgrade/downgrade на временной схеме и компиляцией
PostgreSQL DDL. Реальную PostgreSQL блокировку конкурентных генераторов
локально не запускали; на сервере первоначальный preview использует настоящие
ограничения расписания и базу PostgreSQL.

Проверено: 26 новых сценариев и 71 существующий тест расчётов, оплаты и записи
прошли; сборка интерфейса и ESLint прошли. Установщик проверен на временной
копии: предварительная проверка, повторная установка, остановка при ручных
правках, защита путей и откат при ошибке записи.
Три старых теста поддельного Lesson не имеют source_status и падают так же
на неизменённом HEAD; они не являются подтверждением ошибки этого обновления.
Полную независимую ревизию не заявляем: внешний просмотр выявил два
пограничных случая, оба исправлены и покрыты тестами, затем просмотр прервался.
